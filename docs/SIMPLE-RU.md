# ae2Colony — очень простая схема (сундук + стройка колонии)

Скрипт **уже делает** главное: смотрит, **что колония просит на складе**, и **достаёт это из AE2** (или заказывает автокрафт, если рецепт есть).  
Тебе нужно только **правильно поставить блоки** и **одну строку** в скрипте, если сундук не там.

---

## Шаг 1. Блоки (как на твоём скрине)

1. **ME Bridge** — стоит **в сети AE2** (фиолетовые кабели к контроллеру).
2. **Сундук** — чаще всего **СВЕРХУ на ME Bridge** (как у тебя на картинке).
3. **Advanced Computer** — рядом, с **проводным модемом** к сети, где виден `me_bridge` и `colony_integrator`.
4. **Colony Integrator** — стоит **внутри зоны колонии** (иначе скрипт упадёт с ошибкой).

Скрипт **ничего не кладёт «в компьютер»** — он кладёт в **сундук у моста** (или куда ты укажешь).

---

## Шаг 2. Куда выгружать

**Вариант A — править сам `ae2Colony.lua`** (как раньше): вверху файла `exportSide` / `exportChestPeripheral`.

**Вариант B (v0.5+):** положи рядом файл **`ae2colony_config.lua`** — скопируй с GitHub [`ae2colony_config.example.lua`](https://github.com/TheDR-lul/ae2colony-atm10/blob/main/ae2colony_config.example.lua) и переименуй. В терминале компьютера появится строка `Merged ae2colony_config.lua`.

### Сундук на мосту (по умолчанию)

```lua
exportSide = "top"
exportChestPeripheral = nil
```

(в **config** это поля таблицы `return { ... }`, не `local`)

### Сундук сбоку от моста

Поставь сундук **вплотную** к мосту с нужной стороны и поменяй на одно из:

`bottom`, `front`, `back`, `left`, `right`

(Это стороны **относительно самого моста**, не компьютера.)

### Сундук далеко, но на **проводном модеме**

1. В компьютере запусти программу **`peripherals`** и найди строку с твоим сундуком — там будет **имя**, типа `minecraft:chest_3`.
2. Укажи имя в **`ae2Colony.lua`** (как раньше):

```lua
local exportChestPeripheral = "minecraft:chest_3"  -- your peripheral name
```

или в **`ae2colony_config.lua`**:

```lua
return {
  exportChestPeripheral = "minecraft:chest_3",
}
```

Тогда **`exportSide` игнорируется** — выгрузка идёт прямо в этот сундук по сети модемов.

## Шаг 3. Запуск (две ссылки)

**Свежая версия (монитор + колония + config):**

```text
wget run https://raw.githubusercontent.com/TheDR-lul/ae2colony-atm10/main/ae2Colony.lua
ae2Colony
```

**Замороженная v0.4.6** (если боишься регрессий — без нового UI колонии):

```text
wget run https://raw.githubusercontent.com/TheDR-lul/ae2colony-atm10/main/releases/ae2Colony-v0.4.6.lua
ae2Colony
```

Или один раз сохрани `startup.lua` с одной строкой:

```lua
shell.run("ae2Colony")
```

После этого **перезагрузка компьютера = автозапуск** (это и есть «кнопка»).

## Что ты увидишь, если всё ок

- **Вторая строка монитора (v0.5+):** коротко колония — сайты стройки, жители, счастье; справа полоска до следующего опроса AE2.
- Блок **`COLONY`:** активные заказы стройки (без точного % блоков — такого API нет). Подробнее: [MONITOR-AND-COLONY-UI.md](https://github.com/TheDR-lul/ae2colony-atm10/blob/main/docs/MONITOR-AND-COLONY-UI.md)
- На мониторе: **`[SENT]`** — предметы **улетели в сундук**.
- **`[CRAFT]`** — в AE2 **заказан крафт**, потом обычно на следующем круге пойдёт **`[SENT]`**.
- **`[MISSING]`** — в AE2 **нет шаблона** на этот предмет (надо один раз добавить рецепт в терминал шаблонов). Скрипт **не умеет сам нарисовать** шаблон — это ограничение модов, не «сломанный сундук».

---

## Если сундук пустой

1. Проверь **`exportSide`** / **`exportChestPeripheral`** (см. выше).
2. Убедись, что в AE2 **реально есть** этот предмет или **автокрафт**.
3. Колония должна **что-то запрашивать** — если заявок нет, будет сообщение вроде «No colony requests».

Если хочешь, скинь **скрин сверху** (мост + сундук + компьютер) — скажу, какое слово поставить в `exportSide`.

## Частый вопрос: «Оно смотрит, что уже в сундуке / у строителя, чтобы не вывалить дважды?»

**Сундук и инвентарь строителя скрипт по-прежнему не сканирует** (нет API «заглянуть в руки курьера»).

Но начиная с **v0.4.6** скрипт ведёт **журнал уже выгруженного** по каждой строке заявки (`fingerprint|id@куда`) и хранит его в файле на диске компьютера:

- **`ae2colony_export_ledger.json`** (имя меняется переменной `exportLedgerFile` вверху скрипта).

Пока колония в `getRequests()` показывает **тот же большой счётчик**, а ты уже выгрузил часть в сундук, скрипт **вычитает своё «уже отправил»** и не будет снова тянуть из ME те же **уже выгруженные** штуки (пока заявка не исчезнет или число не уменьшится).

Если **удалишь** `ae2colony_export_ledger.json`, счётчики «уже выгруженного» обнулятся.

Плюс исправлен баг: при **частичном экспорте** из ME крафт заказывается только на **остаток**, а не на полный запрос ещё раз.
